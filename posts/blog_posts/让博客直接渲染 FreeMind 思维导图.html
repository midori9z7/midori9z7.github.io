让博客直接渲染 FreeMind 思维导图

Midori9z7 · 2026 Sep 19

这篇记录的是思维导图渲染的全过程。仓库里放 FreeMind 的源文件了。

一、起因

显然最省事的做法是导出图片：FreeMind[4] 里画完，导出一张 PNG，<img> 一贴完事，但是深色模式做不了啊。导出的图自带白底黑字，贴到纯黑的页面上就是一块白砖。做两张图（浅色一张、深色一张）再按 prefers-color-scheme 切换能解决，但每次改图都要导出两次、改两个文件名、重贴两次路径。

二是图和文分家，进了 git 看不出改了什么，想微调一个措辞也得回到 FreeMind 里重来一遍导出流程。

所以换了个思路：仓库里只放 .mm，让页面自己去读、自己去画。

二、为什么是 .mm

FreeMind 的 .mm 本质上就是一个 XML 文本，简单到可以用几行代码讲完：一个 <map>，里面一个根 <node>，每个节点把自己的文字放在 TEXT 属性里，子节点就是嵌套的 <node>。

<map version="1.0.1">
  <node TEXT="根节点">
    <node TEXT="分支一">
      <node TEXT="叶子"/>
    </node>
    <node TEXT="分支二" FOLDED="true">……</node>
  </node>
</map>

是纯文本，就意味着它能进 git、能 diff、改一次只覆盖一个文件；也意味着里面的颜色、字体可以完全不写死在图里，交给页面的 CSS 决定。

四、实现

4.1 把 .mm 读成一棵树

用 DOMParser[5] 解析 XML，然后从根节点递归下来。这里有两个细节：只认直接的 <node> 子元素（跳过 <font>、<edge>、<icon> 这些兄弟），以及每个节点都必须带 children 数组，叶子节点也不能省——原因在第五节。

function build(el) {
  var node = {
    content: escapeHTML(el.getAttribute('TEXT') || ''),
    children: []
  };
  for (var i = 0; i < el.children.length; i++) {
    var child = el.children[i];
    if (child.tagName === 'node') node.children.push(build(child));
  }
  if (el.getAttribute('FOLDED') === 'true') node.payload = { fold: 1 };
  return node;
}

节点文字要转义成 HTML 实体。markmap 会把内容当 HTML 插进去，FreeMind 的节点里只要有一个 & 或者尖括号，不转义就会把结构写坏。

4.2 按需加载两个依赖

画图交给 markmap[1]。它的浏览器版是一个 IIFE，导出到全局 window.markmap[2]，但不自带 d3[3]——包装函数的签名是 (exports, d3)，得先有全局d3才能跑。所以两个文件都要有，我把它们下载到 vendor/ 自托管，不用 CDN：少一个外部依赖，也不怕哪天链接失效。

function loadScript(src) {
  return new Promise(function (resolve, reject) {
    var s = document.createElement('script');
    s.src = src;
    s.onload = resolve;
    s.onerror = function () { reject(new Error('加载失败：' + src)); };
    document.head.appendChild(s);
  });
}

function loadLibs() {
  if (!libs) {
    libs = loadScript(base + 'vendor/d3.min.js')
      .then(function () {
        return loadScript(base + 'vendor/markmap-view.min.js');
      });
  }
  return libs;
}

关键在于这两个脚本只在页面上真的出现导图时才注入——后来连这一步都往后推迟了，要等导图滚进视野。没有导图的文章不会多下这三百 KB 里哪怕一个字节；一页挂三十张导图，开头也只先拉看得见的那几张。

4.3 交给 markmap 画

拿到树之后，new 一个实例、setData()、fit()：

var mm = new window.markmap.Markmap(svg, {
  autoFit: true,
  initialExpandLevel: -1,
  zoom: false,
  pan: false,
  color: function () { return line; },
  lineWidth: function () { return 1.1; }
});
mm.setData(tree).then(function () { mm.fit(); });

颜色只给一个，不按层级分色——彩虹色的导图放进一篇文章里太吵，单色的连线和正文更搭。文字颜色不走这个参数，见下一节。

4.4 让颜色跟着主题走

markmap 把自带的 CSS 内联成一个 <style> 塞进 SVG，里面用一组 CSS 变量控制外观：--markmap-text-color、--markmap-circle-open-bg、--markmap-font 等等。所以文字颜色不用写进 JS，只要在自己的 CSS 里把这几个变量重新指一遍，指向页面的变量即可：

.mindmap .markmap {
  --markmap-font: inherit;
  --markmap-text-color: var(--ink);
  --markmap-circle-open-bg: var(--paper);
}

连线颜色是个例外——它是 SVG 的属性，不是 CSS 变量，只能由 color 参数给定。做法是在渲染前用 getComputedStyle[6] 把当前的 --mm-line 读成一个具体色值传进去；再监听 prefers-color-scheme[7] 的变化，系统一换主题就重画一遍。

4.5 温馨小提醒

导图渲染失败的原因无非几种：文件不存在、XML 坏了、依赖没加载上。这些都要变成能看懂的话，而不是一片空白。出问题时把容器换成一句说明加一个「下载 .mm 源文件」的链接；正常渲染时，图下面也会常驻一个指向源文件的链，方便直接拿走原始文件。

五、三个坑

一是 color 和 lineWidth 必须是函数。 第一版页面加载后导图区域全空，控制台里是 TypeError: n is not a function。查下来：markmap 文档里写着颜色可以传数组、线宽可以传数字来简写，但那个简写只在它的 deriveOptions() 里生效，而 Markmap 的构造函数并不调用它——直接把数组塞进 options，它就会在渲染时把数组当函数调用。

二是每个节点都必须带 children，叶子也不能省。 第二版解析器为了省字节，在没有子节点时把 children 删掉了，结果报 Cannot read properties of undefined (reading 'map')。markmap 在算连线时直接写了 node.children.map(...)，不像遍历那样容忍 undefined。

三是样式优先级。 markmap 内联的那个 <style> 在文档里的位置比 paper.css 更靠后，两边都写 .markmap { --markmap-text-color: ... }，同权重下后写的赢——深色模式下文字仍是它默认的深灰，在纯黑背景上几乎看不见。把自己的选择器写成 .mindmap .markmap，用权重压过去就好。

还有一个不算坑但容易卡住的点：Markmap.create() 内部是异步的，渲染阶段的报错会变成未捕获的 promise，外层包 try/catch 或 .catch() 都接不到，页面上只会静悄悄地空着。所以这里没用 create()，而是自己 new 实例、setData() 之后接 .catch()。

六、取舍

默认关掉了滚轮缩放和拖动平移。开着的时候，鼠标只要停在导图上，滚轮就变成缩放，页面滚不动，搞得我有点难受。想开的话，把 zoom 和 pan 改成 true 就行。

解析器只读 TEXT。字体、图标、节点配色、备注、箭头链接都不还原，统一走文章的样式。对纯文字导图来说这足够了；真要还原富文本，得换成专门处理 FreeMind 格式的组件，代价是包体和复杂度都上一个台阶。 其实我觉得这挺好的很干净。

导图会按容器大小自动缩放，所以层次特别深、节点特别长的图会缩得比较小。

八、使用

在 FreeMind 里画完存成 .mm，丢进 mindmaps/，文章里写两行：

<div class="mindmap" data-src="/mindmaps/xxx.mm"></div>
<script src="/mindmap.js" defer></script>

一个页面可以放多张，每个 div 写自己的 data-src。没有导图的文章第二行可以不写。

九、零元购

GitHub Pages 对公开仓库免费，FreeMind 是免费软件，d3 和 markmap 分别是 ISC 与 MIT 授权，而且已经下载进仓库自托管，不依赖任何 CDN 账号。唯一要留意的是 GitHub Pages[8]站点 1 GB 左右、每月约 100 GB 流量但是我仓库现在总共五百多 KB大概一辈子用不到限制的。

十、结语

总的来说反正我写的时候也不用想，导图就是仓库里的一个文本文件，改完覆盖，页面刷新就变。代价是多写了一百多行 JS，以及踩了几个坑。呃反正我也写不太好能跑就行。
